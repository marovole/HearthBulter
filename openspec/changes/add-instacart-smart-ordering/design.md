## Context

HearthBulter 需要扩展到美国市场，核心价值主张是「AI 主动规划 → 一键购物」。现有系统已具备完整的餐食规划、AI 推荐、购物清单生成能力，但电商集成仅支持中国平台。

**约束条件**:

- 4 周 MVP 时间窗口
- 单一平台深度集成（Instacart）
- 跳转结算模式（非应用内支付）
- 预算控制功能延后

## Goals / Non-Goals

**Goals**:

- 实现 Instacart OAuth 授权和购物车 API 集成
- 实现智能时机触发的周计划推荐
- 实现对话式计划调整能力
- 验证「AI 主动推荐 → 一键购物」的核心价值假设

**Non-Goals**:

- 多平台比价（延后）
- 应用内支付闭环（使用跳转模式）
- 完整的食材→商品匹配算法（MVP 用样品数据）
- 预算控制功能（延后）

## Decisions

### Decision 1: Instacart Connect API vs Affiliate API

**选择**: Instacart Connect API

**原因**:

- Connect API 支持购物车预填充，用户体验更好
- Affiliate API 仅支持链接跳转，无法预填购物车
- Connect API 支持商品搜索，便于食材匹配

**替代方案**:

- Affiliate API: 更简单但功能受限
- 自建爬虫: 违反 ToS，不可行

### Decision 2: 智能时机触发架构

**选择**: 后台定时任务 + 多因素加权评分

**架构**:

```
┌─────────────────────────────────────────┐
│  Cron Job (每日运行)                     │
│  ↓                                      │
│  遍历所有用户                            │
│  ↓                                      │
│  计算触发分数                            │
│  • 日历事件权重: 30%                     │
│  • 消费周期权重: 25%                     │
│  • 库存状态权重: 25%                     │
│  • 行为习惯权重: 20%                     │
│  ↓                                      │
│  分数 > 阈值 → 生成周计划 → 发送邮件      │
└─────────────────────────────────────────┘
```

**原因**:

- 后台任务避免阻塞用户请求
- 多因素加权提供灵活的触发策略
- 阈值可调，便于 A/B 测试

### Decision 3: 全局悬浮助手实现

**选择**: React Portal + Zustand 全局状态

**原因**:

- Portal 确保 z-index 层级正确
- Zustand 轻量，与现有架构一致
- 支持跨页面状态保持

### Decision 4: 食材匹配策略

**MVP 阶段**: 样品数据 + 简单字符串匹配

**后续迭��**:

- AI 语义匹配
- 用户纠正学习
- 品牌偏好记忆

## Risks / Trade-offs

| 风险                   | 影响 | 缓解措施                                    |
| ---------------------- | ---- | ------------------------------------------- |
| Instacart API 访问受限 | 高   | 提前申请开发者账号，准备 Affiliate 降级方案 |
| 食材匹配准确率低       | 中   | MVP 用样品数据，允许用户手动修正            |
| 智能时机触发过于频繁   | 中   | 设置用户级别的触发冷却期（7天）             |
| 邮件打开率低           | 低   | 优化邮件标题，添加 Push 通知作为备选        |

## Migration Plan

1. **Phase 1 (Week 1-2)**: Instacart API 集成 + 食材匹配
2. **Phase 2 (Week 2-3)**: 智能时机触发 + 邮件通知
3. **Phase 3 (Week 3-4)**: 全局悬浮助手 + 端到端流程

**回滚策略**:

- 功能开关控制新功能可见性
- 数据库变更使用可逆迁移
